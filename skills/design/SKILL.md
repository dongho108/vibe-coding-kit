# /design 디자인

## 이 스킬의 위치

**디자인 지식을 직접 갖지 않는다.** 같이 설치된 외부 스킬을 부르고,
그 결과를 우리 기본값(shadcn/ui + Tailwind)에 맞게 강제하는 것만 한다.

| 쓸 것 | 언제 |
|---|---|
| `ui-ux-pro-max` | 스타일·팔레트·폰트 조합 고를 때. 검색 스크립트가 있다 |
| `frontend-design` | 실제 화면을 만들 때. 흔한 AI 티를 없애는 게 목적 |
| `web-design-guidelines` | 다 만든 뒤 간격·타이포·접근성 점검 |

## 반드시 지킬 것

1. **선택지를 3개 이상 주지 않는다.** 초보는 고르지 못한다.
   2개를 보여주고 "이게 더 어울릴 것 같은데 어떠세요"처럼 추천을 붙인다.
2. **색을 사용자가 직접 고르게 하지 마라.** 서비스 성격에서 뽑아 제안하고 확인만 받는다.
3. **한국어 서비스다.** 폰트는 한글이 제대로 나오는 것으로 고른다.
   Pretendard가 무난하고, 구글 폰트라면 Noto Sans KR.
   영문 전용 폰트를 골라놓고 한글이 깨지는 게 가장 흔한 사고다.
4. **직접 CSS를 쓰지 않는다.** Tailwind 클래스와 shadcn 컴포넌트로만 간다.

## 절차

### 1단계. 톤 정하기

기획서를 읽고 서비스 성격을 파악한 뒤, `ui-ux-pro-max` 의 검색으로 후보를 찾는다.

```bash
python "${CLAUDE_PLUGIN_ROOT}/.claude/skills/ui-ux-pro-max/scripts/search.py" \
  "<서비스 성격 키워드>" --design-system -p "<서비스 이름>"
```

나온 것 중 2개를 골라 사용자에게 말로 설명한다. 스타일 이름을 그대로 던지지 마라.

```
두 가지 방향이 있어요.

A. 깔끔하고 조용한 느낌. 흰 배경에 글씨 위주고, 신뢰감이 중요한 서비스에 어울려요.
B. 색이 또렷하고 활기찬 느낌. 젊은 사용자를 노릴 때 좋아요.

서비스 성격을 보면 A가 맞을 것 같은데 어떠세요?
```

### 2단계. shadcn/ui 설치

Next.js 프로젝트가 아직 없으면 `/stack` 을 먼저 돌리라고 안내한다.
(`/design` 과 `/stack` 은 순서를 바꿔도 되지만, 시안을 실제 코드로 만들려면 프로젝트가 필요하다.)

```bash
npx shadcn@latest init
```

이어서 이 서비스에 필요한 컴포넌트를 받는다. 화면 목록을 보고 필요한 것만 고른다.

```bash
npx shadcn@latest add button card input form dialog
```

**한 번에 다 받지 마라.** 안 쓰는 컴포넌트가 쌓이면 나중에 뭐가 뭔지 모르게 된다.

### 3단계. 토큰 고정

`app/globals.css` 의 CSS 변수와 폰트를 정한 톤에 맞춰 고친다.

정해야 할 것은 이게 전부다.

- 주 색상 하나 (버튼, 링크)
- 배경과 글자색 (라이트·다크)
- 폰트 (제목·본문 같은 것으로 통일)
- 모서리 둥글기

**색을 여러 개 만들지 마라.** 주 색상 하나에 회색 계열이면 충분하다.
색이 늘어날수록 초보가 만든 티가 난다.

### 4단계. 화면 시안

기획서의 화면을 하나씩 만든다. `frontend-design` 을 여기서 부른다.

**순서는 랜딩부터다.** 사용자가 가장 먼저 보게 될 화면이고,
눈에 보이는 결과가 나와야 다음 단계까지 버틴다.

각 화면을 만들고 나면 브라우저에서 확인시킨다.

```bash
npm run dev
```

`agent-browser` 로 직접 열어 스크린샷을 찍어 보여줘도 된다.

### 5단계. 점검

전체 화면이 나오면 `web-design-guidelines` 로 훑는다.

- 모바일에서 깨지지 않는가 (한국은 모바일 비중이 절대적이다)
- 글자가 너무 작지 않은가
- 버튼이 눌러야 할 것처럼 보이는가
- 한글이 제대로 렌더링되는가

## 완료 확인

기획서에 적힌 화면 전부에 시안이 있고, `npm run dev` 로 띄워서 모바일 폭에서도 깨지지 않는다.
