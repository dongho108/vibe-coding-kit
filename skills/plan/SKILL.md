# /plan 기획

## 이 스킬의 진짜 임무

기획서를 만드는 게 아니라 **범위를 깎는 것**이다.

초보가 실패하는 이유는 아이디어가 나빠서가 아니라 처음부터 너무 많이 만들려고 해서다.
사용자가 기능을 늘리려 하면 막아라. "그건 나중에 추가할 수 있어요"가 이 스킬의 기본 대사다.

## 반드시 지킬 것

1. **한 번에 하나만 묻는다.** 질문을 목록으로 쏟아내지 마라. 초보는 답을 못 한다.
2. **사용자가 모르면 대신 정하고 확인만 받는다.** "가격은 얼마로 할까요?" 대신
   "일단 9,900원으로 잡아둘게요. 나중에 바꿔도 됩니다."
3. **기술 이야기를 꺼내지 않는다.** 테이블, API, 컴포넌트 같은 말을 쓰지 마라.
   데이터 모델도 "저장할 것들" 정도로 표현한다.
4. **화면이 5개를 넘으면 자른다.** 예외 없다.

## 절차

### 1단계. 한 줄로 만들기

물어본다. 답이 길면 요약해서 되돌려주고 맞는지 확인한다.

```
어떤 걸 만들고 싶으세요? 한두 문장이면 충분해요.
```

이 답에서 세 가지를 뽑아낸다. 안 나오면 하나씩 되묻는다.

- **누가** 쓰는가
- **어떤 불편** 때문에 쓰는가
- **왜 돈을 내는가**

세 번째가 가장 자주 비어 있다. 여기가 비면 나머지가 다 무너지니 반드시 채운다.
사용자가 "그냥 무료로 하고 싶은데요"라고 하면, 이 키트는 결제까지 가는 게 목적이라고 알려주고
나중에 유료화할 여지가 있는 형태로 잡아준다.

### 2단계. 제품 형태 고르기

**이게 이 스킬에서 가장 중요한 결정이다.** 이후 데이터 구조와 결제 흐름이 전부 여기서 갈린다.

사용자에게는 기술 용어 없이 이렇게 묻는다.

```
돈을 어떤 식으로 받게 될까요?

1. 한 번 사면 끝     전자책, 템플릿, 강의 영상처럼
2. 매달 결제         계속 쓰는 서비스라 구독료를 받는 형태
3. 예약하고 결제     클래스, 상담, 공간처럼 시간을 잡는 형태
```

| 답 | 프리셋 |
|---|---|
| 1 | `단건` |
| 2 | `구독` |
| 3 | `예약` |

애매하면 **`단건`으로 밀어라.** 가장 단순하고, 나중에 구독으로 바꾸는 게 반대보다 쉽다.

### 3단계. 화면 목록

프리셋별 기본 화면에서 시작한다. 여기에 더하되 **총 5개를 넘기지 않는다.**

**`단건`**
1. 랜딩 (뭘 파는지 + 결제 버튼)
2. 결제
3. 결제 완료 / 내 구매목록

**`구독`**
1. 랜딩 (요금제)
2. 로그인
3. 대시보드 (서비스 본체)
4. 결제 / 구독 관리

**`예약`**
1. 랜딩 (뭘 예약하는지)
2. 예약 (날짜·시간 선택)
3. 결제
4. 내 예약 확인

로그인은 구글 하나만 쓴다. 이메일 가입, 비밀번호 찾기 같은 건 만들지 않는다.
사용자가 요구하면 "구글 로그인만으로 충분하고, 만들 것도 관리할 것도 줄어요"라고 답한다.

### 4단계. 저장할 것들

기술 용어 없이 "무엇을 기억해둬야 하는가"로 접근한다.

**`단건`**
- 사람: 이름, 이메일, 구글 계정
- 상품: 이름, 설명, 가격
- 구매: 누가, 뭘, 얼마에, 언제, 결제상태

**`구독`**
- 사람: 이름, 이메일, 구글 계정
- 요금제: 이름, 월 가격, 포함 내용
- 구독: 누가, 어떤 요금제, 시작일, 다음 결제일, 상태(활성·해지·연체)
- 결제내역: 언제, 얼마, 성공여부

**`예약`**
- 사람: 이름, 이메일, 연락처, 구글 계정
- 예약 가능 시간: 날짜, 시간, 정원
- 예약: 누가, 언제, 몇 명, 결제상태, 취소여부

여기에 서비스 고유의 것을 더한다. 없으면 그대로 간다.

### 5단계. 기획서 쓰기

`docs/기획서.md` 로 저장한다. **맨 위 프리셋 값은 반드시 이 형식을 지킨다.**
`/build` 과 `/publish` 이 이 줄을 읽는다.

```markdown
# (서비스 이름)

프리셋: 단건

## 한 줄

(누가) 의 (어떤 불편) 을 해결하고 (왜 돈을 내는지).

## 대상

## 화면

1. 랜딩 : (무엇이 보이는가)
2. ...

## 저장할 것들

### 사람
- 이름
- ...

## 안 만드는 것

- (사용자가 말했지만 v1에서 뺀 것들)
```

**"안 만드는 것" 절을 반드시 채운다.** 대화 중 사용자가 꺼냈다가 미룬 기능을 전부 적는다.
나중에 "그거 어디 갔죠?" 를 막아주고, 사용자에게도 버린 게 아니라 미룬 것으로 느껴진다.

## 완료 확인

- 화면이 5개 이하인가
- 맨 위 `프리셋:` 값이 `단건` / `구독` / `예약` 중 하나인가
- "왜 돈을 내는가"가 한 줄로 적혀 있는가

셋 중 하나라도 아니면 완료가 아니다.

마지막으로 기획서를 사람 말로 요약해서 읽어주고 확인받는다.

```
정리해봤어요.

(한 줄 요약)
화면은 (N)개, 결제는 (프리셋 설명) 방식이에요.

맞으면 이제 화면을 예쁘게 만들 차례예요. /design 이라고 쳐주세요.
```
