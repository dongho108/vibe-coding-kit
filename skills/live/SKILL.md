# /live 실결제 전환

## 대원칙: 토스 공식 문서만 본다

결제 연동·심사·키·수수료 정보는 **토스페이먼츠 공식 출처만** 근거로 쓴다.

- `docs.tosspayments.com` (페이지 주소 끝에 `.md` 를 붙여 curl로 원문을 받는다. 목록은 `https://docs.tosspayments.com/llms.txt`)
- `www.tosspayments.com` (요금, FAQ, 블로그), `onboarding.tosspayments.com` (신청)

다른 블로그·커뮤니티 글은 쓰지 않는다. 정책은 바뀌므로 **각 단계에서 해당 페이지를 다시 받아 읽고** 이 파일과 다르면 공식 문서를 따른다.
공식 문서에서 못 찾은 내용은 "토스 문서에는 없는 키트의 권장"이라고 밝히고 말한다.

## 이 스킬이 하지 않는 것

- **서류 제출과 신청은 사용자가 직접 한다.** 사업자등록, 통신판매업 신고, 전자결제 신청은 본인 인증과 서류가 필요하다.
  Claude는 어디서 무엇을 누르는지 안내하고, 사이트 쪽 코드 작업을 맡는다.
- **라이브 키를 `.env.local` 에 넣지 않는다.** 라이브 키는 Vercel의 Production 환경에만 넣는다 (5단계).

## 시작 전에

- `/pay` 로 테스트 결제가 끝까지 도는 상태인지 확인한다. 안 되면 거기부터 한다.
  토스 심사 조건에 **"실제 판매가 이루어지는 쇼핑몰(앱) 결제 연동도 완료돼야 해요"** 가 있다.
- `/publish` 로 배포된 주소가 있어야 한다. 심사는 실제 사이트를 본다.
- `docs/기획서.md` 의 프리셋(단건·구독·예약)을 읽는다. 구독은 추가 계약이 있다.

## 1단계. 자격 확인

한 번에 하나씩 묻는다.

**사업자등록이 되어 있나요?**

- 전자결제 신청 화면의 첫 칸이 사업자등록번호다. 없으면 신청할 수 없다.
- 토스 FAQ: "비사업자이신 경우, 7일 이내에 배송되는 유형의 기성제품에 한하여 입점이 가능합니다."
  즉 서비스·콘텐츠·구독·예약은 사업자등록이 필요하다.
- 토스가 무료로 사업자등록과 통신판매업 신고를 함께 해주는 신청을 운영한다.
  https://onboarding.tosspayments.com/business-registration/intro
  (FAQ 기준 "단독대표이고, 개인사업자인 경우에만 이용 가능")

**통신판매업 신고를 했나요?**

- 온라인 판매는 통신판매업 신고가 필수다. 다만 직전연도 온라인 판매가 50건 미만이거나 간이과세자면 면제된다.
  ([통신판매업](https://docs.tosspayments.com/resources/glossary/online-business.md))
- 토스 심사 안내: "통신판매업 신고번호가 없을 경우 국민카드 심사가 제외돼요."
  면제 대상이어도 국민카드를 받으려면 신고하는 편이 낫다고 알려준다.

## 2단계. 심사용 사이트 준비 (코드 작업)

토스 블로그 [카드사 심사 안내](https://www.tosspayments.com/blog/articles/semo-7)를 받아 읽고, 사이트가 조건을 채우는지 하나씩 확인한다.
빠진 것은 `feature` 스킬의 절차로 만든다. 검증도 `feature` 의 검증을 그대로 돌린다.

| 조건 (토스 안내) | 확인 |
|---|---|
| 바닥글에 상호명, 대표자명, 사업자등록번호, 사업장 주소, 전화번호, 통신판매업 신고번호 | 사용자에게 값을 받아 `app/footer` 에 넣는다 |
| "상품 금액과 결제 금액이 같아야 해요" | 화면 가격과 DB 가격이 같은지, 결제창 금액과 같은지 |
| 품절·샘플이 아닌 바로 살 수 있는 상품 1개 이상, 제대로 뜨는 상품 사진 | 임시 사진(Unsplash)과 임시 상품을 실제 것으로 바꾼다 |
| 비실물 상품(콘텐츠·서비스)은 제공기간과 환불정책 표시 | 상품 상세나 결제 전 화면에 적는다. 예약은 취소 규정도 |
| 회원만 살 수 있으면 심사용 테스트 계정 | 구글 로그인 전용이면 심사용으로 쓸 계정을 사용자가 준비해 계약 담당자에게 전달 |

전화번호는 070, 0505, 080, 전국대표번호, 휴대폰번호도 된다고 안내되어 있다.
바닥글 값은 **사용자에게 받은 그대로** 넣는다. 지어내지 않는다.

## 3단계. 전자결제 신청 (사용자가 직접)

1. 신청: https://onboarding.tosspayments.com/registration/business-registration-number?from=inbound
   (토스페이먼츠 홈페이지 → 결제 서비스 → 모든 결제 서비스 → 이용 신청하기와 같은 곳)
2. 서류는 사업자 유형마다 다르다. FAQ 기준 주민번호 뒷자리까지 보이는 신분증(주민등록증·운전면허증)과 통장사본이 필요하고,
   개인사업자는 대표자 명의나 사업자 명의 계좌로만 정산받는다. 신청 화면의 안내를 따른다.
3. **구독이면 결제 서비스 선택에서 자동결제(빌링)도 신청한다.**
   토스 문서: "자동결제는 리스크 검토 및 추가 계약 후 사용할 수 있습니다. 정기 구독형 서비스가 아니라면 정책적으로 자동결제 사용이 제한되니 유의하세요."
4. 심사 순서: 입점 계약 심사 → 카드사 심사. 카드사 심사는 "평균 영업일 기준 7일" (지연될 수 있음).
5. 비용은 [요금 안내](https://www.tosspayments.com/about/fee)를 사용자와 같이 연다.
   2026년 9월 확인 기준 가입비 220,000원(최초 1회), 연관리비 110,000원, 카드 수수료 3.4%(부가세 별도).
   **바뀔 수 있으니 반드시 페이지에서 다시 확인시킨다.**

## 4단계. 내 테스트 키로 먼저 바꾼다

라이브로 바로 가지 않는다. 신청이 끝나면 개발자센터에서 **내 상점의 테스트 키**가 보인다.

- 개발자센터 → API 키 (https://developers.tosspayments.com/my/api-keys) → 신청한 상점(MID) 선택
- 단건·예약: 주문서형 연동 키 `test_gck_` / `test_gsk_` (지금까지 쓰던 문서용 키 `test_gck_docs_...` 를 대체)
- 구독: 자동결제로 계약된 MID의 API 개별 연동 키 `test_ck_` / `test_sk_`
- `.env.local` 과 Vercel 환경변수(Preview, Development)의 두 값을 바꾼다.

그리고 **웹훅을 등록한다.** 문서용 키를 쓰는 동안은 못 했던 일이다.
[웹훅 가이드](https://docs.tosspayments.com/guides/v2/webhook.md)를 받아 읽고 따른다.

- 개발자센터 → 웹훅 (https://developers.tosspayments.com/my/webhooks) → 웹훅 등록하기
- URL: 배포된 주소의 `/api/webhooks/toss`. localhost는 등록되지 않는다.
- 이벤트: `PAYMENT_STATUS_CHANGED`, `CANCEL_STATUS_CHANGED` (가상계좌를 쓰면 `DEPOSIT_CALLBACK`)
- "웹훅은 상점아이디(MID)별로 설정" 된다. 주문서형 MID와 자동결제 MID를 둘 다 쓰면 각각 등록한다.
- 웹훅 라우트는 10초 안에 200으로 응답해야 한다. 늦으면 최대 7회 재전송된다.

내 테스트 키로 `/pay` 의 테스트 항목을 **처음부터 다시** 돌린다. 개발자센터의 테스트 거래내역에 결제가 찍히는지도 본다.

## 5단계. 라이브 키로 교체

**카드사 심사가 끝난 뒤에 한다.** 심사 결과는 토스가 알려준다.

1. 개발자센터 → API 키에서 같은 MID의 라이브 키를 받는다. 앞이 `live_` 다.
   단건·예약은 `live_gck_` / `live_gsk_`, 구독은 `live_ck_` / `live_sk_`.
   클라이언트 키와 시크릿 키는 한 세트다. 섞으면 `INVALID_API_KEY` 가 난다.
2. **Vercel의 Production 환경에만** 넣는다. Preview·Development와 `.env.local` 은 테스트 키로 둔다.
   이렇게 나눠야 개발하다 실수로 실제 결제가 일어나지 않는다.

   ```bash
   vercel env rm NEXT_PUBLIC_TOSS_CLIENT_KEY production
   vercel env add NEXT_PUBLIC_TOSS_CLIENT_KEY production
   vercel env rm TOSS_SECRET_KEY production
   vercel env add TOSS_SECRET_KEY production
   ```

   키 값은 사용자가 입력 창에 직접 붙여넣게 한다. 대화창에 라이브 시크릿 키를 붙여넣지 말라고 먼저 말한다.
3. 라이브 MID에 웹훅이 등록되어 있는지 개발자센터에서 확인한다.
4. 재배포한다. 환경변수는 빌드 때 들어가므로 재배포해야 반영된다.

## 6단계. 토스 배포 체크리스트

[배포 체크리스트](https://docs.tosspayments.com/guides/v2/deploy-checklist.md)를 받아 한 항목씩 사용자와 확인한다. 우리 서비스에 해당하는 것만.

- 라이브 키인가, 선택된 MID가 맞는가
- 시크릿 키가 코드·GitHub에 노출되지 않았는가 (`git log -p | grep -E 'live_(g)?sk_'` 로 기록까지 확인)
- 제공할 카드사 심사를 통과했는가
- 결제 흐름 전체: 결제창 → 결제수단 → successUrl/failUrl 이동 → 승인
- 취소와 부분 취소가 되는가
- 에러 처리가 되는가
- 데스크톱 브라우저(Chrome, Edge, Firefox, Safari, Whale)와 모바일에서 되는가

## 7단계. 첫 실결제 확인

> 토스 문서에는 없는 **키트의 권장**이다. 사용자에게도 그렇게 말한다.

가장 싼 상품을 사용자 본인 카드로 실제 결제하고, 바로 관리 화면이나 취소 API로 전액 취소해본다.

- 토스 문서 기준 카드 결제는 매입 전 취소하면 취소 직후 환불되고, 매입 이후나 부분 취소는 영업일 3~4일 걸린다.
- 카드 결제를 취소하면 결제 때 부과된 수수료도 함께 환급된다.
- 결제 후 DB 주문이 `paid`, 취소 후 `cancelled` 가 되는지, 웹훅이 들어왔는지 본다.

구독은 카드 등록 → 첫 결제 → 해지까지 한 번 해보고 결제를 취소한다.

## 8단계. 알려줄 것

- 정산 주기는 계약마다 정해진다. 토스 요금 안내는 "평균 5일 이내 정산", 용어 문서는 "정산 주기는 최소 일주일"이라고 해서
  **계약서에 적힌 주기를 확인하라고** 안내한다.
- 처음에는 월 정산한도가 기본값이다. 한도를 넘으면 초과분은 다음 달 첫 영업일에 지급된다.
- 결제·정산 조회는 토스 상점관리자에서 한다.

## 완료 확인

- 배포된 사이트가 라이브 키로 결제되고, 전액 취소까지 확인했다.
- `.env.local` 과 Vercel Preview·Development는 여전히 `test_` 키다.
- 라이브 MID에 웹훅이 등록되어 있다.

```
이제 실제로 돈을 받을 수 있어요. 첫 결제는 취소해뒀어요.
앞으로 기능을 고칠 때는 내 컴퓨터와 미리보기 주소에서는 테스트 결제로, 실제 사이트에서만 진짜 결제로 돌아가요.
```

## 자주 막히는 곳

| 증상 | 원인 |
|---|---|
| `INVALID_API_KEY` | 클라이언트·시크릿 키가 한 세트가 아니거나 테스트·라이브를 섞었다 |
| 구독 카드 등록이 안 된다 | 자동결제 계약이 안 된 MID의 키다. 라이브에서는 카드 번호 전체가 유효해야 등록된다 |
| 라이브 키를 넣었는데 여전히 테스트 결제 | 재배포를 안 했다 |
| 웹훅이 안 온다 | 라이브 MID에 웹훅을 등록하지 않았다. 웹훅은 MID별이다 |
| 국민카드만 안 된다 | 통신판매업 신고번호가 없으면 국민카드 심사가 빠진다 |
