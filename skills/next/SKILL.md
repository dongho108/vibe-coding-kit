# /next 이어서 하기

사용자는 명령어 순서를 외우지 못한다. 며칠 만에 돌아와서 "이어서 해줘" 한마디만 해도
어디까지 했는지 알고 남은 일을 바로 하게 만드는 것이 이 스킬의 일이다.

그 기반이 **작업 기록 파일** `.claude/worklog/진행상황.md` 다. 모든 진행 스킬이 이 파일을 갱신하고, 이 스킬이 읽는다.

## 작업 기록 파일

### 위치

- 기록: 프로젝트 폴더의 `.claude/worklog/진행상황.md`
- 연결: 프로젝트 폴더의 `.claude/CLAUDE.md` 에 아래 한 줄을 넣는다. 새 세션이 열리면 Claude가 이 파일을 자동으로 읽는다.

  ```markdown
  이 프로젝트는 바이브 코딩 키트로 만드는 중이다. 작업을 시작하기 전에 `.claude/worklog/진행상황.md` 를 먼저 읽는다.
  ```

**작업 기록과 연결 파일은 둘 다 `.claude/` 안에만 둔다.** 루트에 `CLAUDE.md` 나 다른 폴더를 만들지 않는다.
`/build` 의 `create-next-app` 은 폴더에 모르는 파일이 있으면 멈추는데, `.claude/` 는 괜찮다고 인정하는 폴더다.
기획서 같은 서비스 문서(`docs/`)와 작업 기록을 섞지 않으려는 뜻도 있다.

`.claude/` 는 점(.)으로 시작해서 Finder·탐색기에서 기본으로 안 보인다.
사용자가 기록을 보고 싶다고 하면 파일을 찾으라고 하지 말고 Claude가 읽어서 보여준다.
`.gitignore` 에 `.claude` 가 들어가 있으면 빼서 기록이 커밋되게 한다.

### 형식

처음 만들 때 이 틀을 쓴다. 사용자가 열어봐도 알아볼 수 있게 쉬운 말로 적는다.

```markdown
# 진행 상황

> 바이브 코딩 키트가 자동으로 적는 작업 기록이에요. 클로드에게 "이어서 해줘" 라고 하면 여기부터 이어서 해요.

## 지금

- 하는 중: /build 3단계 스키마
- 다음 할 일: 3단계 RLS 정책 적용부터
- 하다 만 것: orders 테이블까지 만듦. bookings 아직
- 사용 환경: 클로드 데스크탑
- 마지막 갱신: 2026-09-29

## 단계

- [x] /start local  환경 확인
- [x] /plan  기획서
- [x] /build local  뼈대와 임시 데이터
- [ ] /design  디자인과 화면
- [ ] /start deploy  GitHub·Vercel 계정
- [ ] /publish only  첫 배포
- [ ] /start accounts  Supabase·Google·토스 계정
- [ ] /build  데이터베이스와 구글 로그인
- [ ] /pay  결제
- [ ] /publish  최종 배포

## 정해진 것 (다시 묻지 않는다)

- 프리셋: 단건
- 디자인: 기본 (Your Next Store 스타일)
- 배포 주소: https://...vercel.app

## 남은 일

- [ ] 리뷰 기능 (사용자가 나중에 하자고 함)

## 기록

- 2026-09-29 /build local 끝. data/products.ts 에 상품 3개
- 2026-09-28 /plan 끝. 전자책 판매, 화면 4개
```

### 적는 규칙

- **단계** 목록은 README의 기본 순서다. 사용자가 다른 길로 가면 (예: `/start` 에서 "전부" 를 골라 계정을 한 번에 만듦)
  실제로 한 대로 체크하고 필요 없는 줄은 지운다. 순서를 사용자에게 강요하지 않는다.
- `/live` 는 목록에 미리 넣지 않는다. 사용자가 먼저 꺼냈을 때만 추가한다. (`/live` 스킬의 원칙과 같다)
- `/publish` 까지 끝나면 단계 목록은 다 체크된 상태로 두고, 이후 일은 **남은 일** 과 **기록** 에 적는다.
- **정해진 것** 에는 사용자가 답한 선택을 적는다. 새 세션이 같은 걸 다시 묻지 않게 하는 곳이다.
- **남은 일** 에는 사용자가 "나중에", "이따가" 라고 미룬 요청과 `/feature` 로 받은 큰 기능 중 안 끝난 것을 적는다.
- **기록** 은 최신이 위로 오게 한 줄씩 쌓는다. 20줄이 넘으면 오래된 것부터 지운다.
- **키·비밀번호·토큰 같은 값은 절대 적지 않는다.** 이 파일은 커밋되고 GitHub에 올라간다. 그런 값은 `.env.local` 에만 있다.
- 날짜는 오늘 날짜로 적는다. "어제" 같은 말은 쓰지 않는다.

### 언제 갱신하나 (모든 진행 스킬 공통)

1. **스킬을 시작할 때** 파일을 읽는다. 없으면 위 틀로 만들고 `.claude/CLAUDE.md` 연결도 넣는다.
   이미 정해진 것은 다시 묻지 않고, 하다 만 것이 있으면 거기부터 한다.
   "지금" 의 하는 중을 이번 스킬로 바꾼다.
2. **단계 하나를 끝낼 때마다** "지금" 과 "기록" 을 고친다. 스킬 전체가 끝날 때까지 미루지 않는다.
   중간에 창이 닫히거나 세션이 끊겨도 마지막으로 끝낸 단계가 남아야 한다.
3. **사용자가 선택을 답하면** 바로 "정해진 것" 에 적는다.
4. **스킬을 끝낼 때** 단계 목록에 체크하고, "다음 할 일" 에 다음 명령을 적는다.
5. **새 세션을 열라고 안내하기 전에** (MCP 연결 등) 반드시 갱신한다. `build` 스킬의 "새 세션으로 넘어갈 때" 참고.

코드와 같이 바뀌었으면 코드 커밋에 함께 넣는다. 기록만 따로 커밋하느라 사용자를 붙잡지 않는다.

## 사용자에게 일 시키는 기준 (모든 진행 스킬 공통)

**웬만하면 사용자에게 시키지 않는다. Claude가 할 수 없는 것만 시킨다.**
사용자는 명령어 순서도, 사이트 메뉴 위치도 외우지 않는다. 시킬 때마다 이탈할 확률이 오른다.

### 할 일을 처리하는 순서

위에서부터 되는 방법으로 한다. 아래로 내려갈수록 사용자 손이 더 간다.

1. **명령어·MCP로 Claude가 직접 한다.** 설치(`node`·`git`·`gh`), Supabase 프로젝트 생성과 키 조회(Supabase MCP),
   Vercel 연결과 환경변수(`vercel` CLI), GitHub 저장소(`gh`) 전부 여기에 해당한다.
   명령어를 사용자에게 치라고 하지 않는다.
2. **브라우저를 Claude가 조작한다.** 명령어·MCP로 안 되는 사이트 설정 (Google Cloud OAuth, Supabase 대시보드 설정 등).
   - 클로드 데스크탑: 앱에 들어 있는 브라우저(`built-in-browser` 스킬)를 쓴다.
   - 터미널: `agent-browser` 를 화면이 보이게(`--headed`) 띄운다.
   - 사용자에게 시키는 건 **그 브라우저에서 로그인하기**와 **"허용" 같은 본인 확인 버튼**뿐이다. 나머지 칸 채우기·버튼 누르기는 Claude가 한다.
3. **외부 브라우저를 열어주고 그것만 시킨다.** 위 둘이 안 될 때만 (예: 브라우저 조작이 막힌 사이트, 비밀 키 복사).
   - 사이트 첫 화면이 아니라 **할 일이 있는 그 페이지**를 Claude가 직접 연다. Mac `open "<주소>"`, Windows `start "" "<주소>"`.
   - 할 일은 한두 줄로만 말한다. "열린 페이지에서 Secret key 옆 복사 버튼을 누르고 '했어' 라고 해주세요."
   - 주소도 같이 적어준다. 브라우저가 안 열렸을 때 눌러서 들어가게.

계정 가입(GitHub·Supabase 등)과 본인 확인처럼 **사용자만 할 수 있는 일**은 3번처럼 정확한 페이지를 열고 짧게 시킨다.

### 비밀 키 받기

비밀 키도 사용자가 손으로 `.env.local` 을 고치게 하지 않는다. 두 가지 다 받는다.

- **기본: 클립보드에서 바로 넣는다.** 키 페이지를 열어주고 복사 버튼만 누르게 한 뒤, Claude가 클립보드를 읽어 파일에 쓴다.
  키가 대화에 한 번도 들어오지 않는다. **값을 화면에 출력하지 않는다** (`echo`·`cat` 금지).

  ```bash
  # Mac. 이름과 접두사만 바꿔 쓴다. Windows는 pbpaste 대신 powershell -command Get-Clipboard
  NAME=SUPABASE_SECRET_KEY; PREFIX=sb_secret_
  V=$(pbpaste | tr -d '[:space:]')
  case "$V" in "$PREFIX"*) ;; *) echo "클립보드에 $PREFIX 로 시작하는 값이 없음"; exit 1;; esac
  touch .env.local; grep -v "^$NAME=" .env.local > .env.local.tmp; printf '%s=%s\n' "$NAME" "$V" >> .env.local.tmp; mv .env.local.tmp .env.local
  printf '' | pbcopy   # 클립보드 비우기
  echo "$NAME 저장됨 (${V:0:8}...)"
  ```

  접두사가 안 맞으면 다른 걸 복사한 것이다. 어느 버튼인지 다시 짚어준다.
- **대화창에 붙여넣어도 받는다.** "붙여넣지 마세요" 라고 말하지 않는다. 받은 값을 바로 `.env.local` (필요하면 Vercel 환경변수)에 쓰고:
  - 그 값을 다시 출력하거나 따라 적지 않는다. 확인은 앞 8자만.
  - 진행상황.md·메모리·커밋·다른 파일에 남기지 않는다.
  - 사용자에게는 "받아서 .env.local 에 넣었어요" 한 줄만 한다.

### 단계가 끝나면 다음 단계로 바로 간다

스킬이 끝날 때 "`/design` 이라고 치세요" 처럼 명령어를 외우게 하지 않는다.

1. 진행상황.md 의 "다음 할 일" 을 적는다.
2. 다음 할 일을 사람 말로 한 줄 말하고 **"이어서 할까요?"** 만 묻는다. 예: "다음은 화면 디자인이에요. 이어서 할까요?"
3. "네"·"응"·"계속" 이면 다음 스킬을 Claude가 바로 불러서 시작한다.
   "나중에" 면 "다음에 오셔서 '이어서 해줘' 라고만 하시면 돼요" 하고 멈춘다.

다음 할 일은 README의 기본 순서(위 "단계" 목록)를 따른다. 사용자에게 순서를 고르게 하지 않는다.
슬래시 명령은 사용자가 원하면 쳐도 되지만, 몰라도 끝까지 갈 수 있어야 한다.

## 절차

### 1. 읽기

`.claude/worklog/진행상황.md` 를 읽는다.

**파일이 없으면** 프로젝트 상태를 보고 만든다. 사용자에게 처음부터 묻지 않는다.

| 이게 있으면 | 끝난 것 |
|---|---|
| `node --version` 이 20 이상 | /start local |
| `docs/기획서.md` 와 맨 위 `프리셋:` | /plan |
| `package.json` 에 `next` | /build local (`data/*.ts` 가 있으면 임시 데이터 단계) |
| `design-system/*/MASTER.md` | /design |
| `gh auth status` 로그인, `.vercel/` 또는 git remote | /start deploy, /publish only |
| `.env.local` 의 Supabase 값 | /start accounts (Supabase 부분) |
| `lib/supabase/` 와 `supabase/migrations/` | /build |
| 토스 결제 코드 (`@tosspayments/` import) | /pay |

확인한 결과로 파일을 만들고, 사용자에게 한 줄로 알린다. "지금까지 된 걸 확인해서 진행 기록을 만들어뒀어요."
판단이 애매한 줄은 체크하지 않는다. 덜 된 걸 된 걸로 적는 것보다 한 번 더 확인하는 게 낫다.

**파일은 있는데 실제 상태와 다르면** (예: 기록엔 /build 끝인데 `package.json` 이 없음) 실제 상태를 믿고 기록을 고친다.

### 2. 알려주기

어디까지 됐고 다음에 뭘 할지 **세 줄 안으로** 말한다.

```
지금까지: 기획, 뼈대, 디자인까지 끝났어요.
다음: 인터넷 주소 만들기
바로 시작할게요.
```

### 3. 이어서 하기

"다음 할 일" 에 해당하는 스킬을 불러서 적힌 단계부터 한다. 사용자가 명령어를 다시 칠 필요 없다.

- "하다 만 것" 이 있으면 그것부터 한다.
- 다음 할 일에 **계정 가입처럼 사용자만 할 수 있는 일**이 끼어 있으면, 시작 전에 사용자가 할 일만 한 줄로 미리 말한다.
  "이번엔 Supabase 가입 한 번만 해주시면 나머지는 제가 해요." 그 외 설명은 하지 않는다.
- 단계 목록이 전부 끝났고 남은 일도 없으면 이렇게 말한다.
  "계획한 건 다 끝났어요. 이제 원하는 기능을 말로 하면 돼요. 예: '리뷰 기능 붙여줘'"
- "남은 일" 이 있으면 목록을 보여주고 어느 것부터 할지 묻는다. 고르면 `/feature` 로 한다.

## 사용자가 "어디까지 했어" 만 물었을 때

2번 알려주기만 하고 멈춘다. 이어서 할지는 묻는다. 묻지도 않았는데 작업을 시작하지 않는다.
